Asked: Asked Claude how to add profile editing to the Sprint 1 architecture, since students and mentors may need to edit their profiles. We wanted an EditProfile.java class that edits the student intake profile and, for mentors, the guidance they offer, only changing the attributes we extend and store ourselves, not the ones living in Shared Core.

Produced: An EditProfile.java row for the Module view table in the API / controller layer, along with updated rows for app.js and MentoringApp.java and additions to the module diagram. It recommended editing through PUT on the existing profile path instead of a separate /editprofile path. It explained that EditProfile cannot inherit from MentorProfile and StudentMatchProfile, and that our classes cannot inherit from Shared Core since it runs in a separate container, so Shared Core data comes through API calls. It also suggested a separate editprofile.html page, an endpoint table, and a risk row for half-saved profiles, which were not asked for.

Changed: We rejected the separate editprofile.html page and the half saved profile risk row. We changed EditProfile from inheriting the profile classes to using them, reading Shared Core data through its API. We kept EditProfile.java in the API / controller layer, choosing mentor or student by the role in the token and editing only the matching attributes we own.
